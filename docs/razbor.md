# Как Гриди разбирает текст

Документ для разработки. Здесь все правила, по которым текст становится страницей: что делает Гриди, что делает модель, где это в коде. У каждого правила номер: в коде он стоит в комментарии, в тестах — в названии проверки. Чтобы поменять правило, найдите его номер, поменяйте код и тест.

Редакции этот документ не нужен. Ей хватает памятки «Как писать текст» в Гриди (кнопка на экране вставки текста).

## 1. Поток

1. **Вставка.** Текст из буфера: HTML размечается по тегам (В1), остальное — один раз по форме строк (В2, В3). Результат виден в режиме «Текст».
2. **Сборка без модели.** Гриди делит текст на блоки по разметке и даёт им роли (С-правила). Это основа: если модель не ответит, страница останется такой.
3. **Модель.** Получает строки с номерами и сборку Гриди, отвечает номерами строк: какие строки — какой блок и роль, что заголовок, пункт, подпись, кнопка, картинка (М-правила). Текст модель не пишет.
4. **Блоки.** Текст каждого блока в разметке. Это единственный источник правды: поля шаблона, превью и выгрузка собираются из него.
5. **Подбор шаблона** (П-правила) и **заполнение полей** (З-правила).
6. **Проверка** (К-правила) и **«Поправить»** (Ф-правила).

## 2. Разметка: строки

Одна грамматика на всю Гриди — `G.lineKind` (core.js). По ней работают разбор, редактор «Текст», промты и пример в промте.

| Строка | Вид | Пример |
| --- | --- | --- |
| `[h1] текст` | заголовок страницы | `[h1] Бизнес-фест 2026` |
| `[h2] текст` | заголовок раздела | `[h2] Программа` |
| `[h3] текст` | заголовок карточки (`[h4]` читается как `[h3]`) | `[h3] На метро` |
| `- текст`, `• текст`, `1. текст` | пункт | `- Доклады — 12 спикеров` |
| `@ текст` | подпись | `@ 12 ноября · Москва` |
| `[кнопка] текст \| ссылка` | кнопка; `[ссылка]`, `[button]`, `[link]` — то же | `[кнопка] Записаться \| https://…` |
| `[картинка] подпись` | картинка; `[фото]`, `[image]`, `[img]` — то же | `[картинка] Зал с участниками` |
| `a \| b \| c` | строка таблицы | `Гость \| Доклады \| 0 ₽` |
| остальное | абзац | |

Заголовок пустой — строка пропускается. «Заголовок» длиннее 120 знаков — абзац. Адрес у кнопки — только если похож на ссылку (`http`, `www.`, `/`, `#`, `mailto:`, `tel:`), иначе всё — текст кнопки.

## 3. Р-правила: связи строк

Связи строк определяются только их положением и формой. Смысл текста не угадывается, пустые строки ничего не значат. Код — `G.parse` (core.js).

| № | Правило | Пример | Зачем |
| --- | --- | --- | --- |
| Р0 | Новый блок начинается с `[h1]`, `[h2]` или строки `---` (лендинг); у статьи — см. С-правила. Без разметки блоки делит модель. | | граница блока видна в тексте |
| Р1 | `@` и `[кнопка]` относятся к строке над ними: под пунктом или `[h3]`-карточкой — к ней, иначе — к блоку. | `- Иван — CEO` / `@ 40 точек` → подпись пункта | подпись и кнопка всегда «чьи-то» |
| Р2 | Пункт делится на заголовок и текст одним разделителем, общим для **всех** пунктов блока: « — » (по первому тире, от 1 пункта), «: » или «Фраза. Текст» (от 2 пунктов), время или дата в начале. Иначе пункты не делятся. | «Приходите заранее — регистрация с 9:00» среди пунктов без тире не делится | одно тире в фразе не превращает её в заголовок |
| Р3 | `[h3]` — карточка; абзацы под ним до следующей размеченной строки — её текст. | `[h3] На метро` / `Станция…` | карточки с длинным текстом |
| Р4 | Заголовок блока — первый `[h1]`/`[h2]`. `[h3]` — заголовок блока, только если он в блоке один, до пунктов и без `[h1]`/`[h2]`. | два `[h3]` подряд — две карточки | раньше первый `[h3]` молча становился заголовком, и текст под ним терялся |
| Р5 | Кнопки пунктов — только если кнопка есть у каждого пункта. Иначе все кнопки — кнопки блока, по порядку. | кнопка под последним пунктом программы — кнопка блока | раньше это решала пустая строка |
| Р6 | Таблица — 2 строки и больше с « \| » и одинаковым числом колонок. Таблица ставится только в шаблон «Таблица», модель её строки не переделывает. | | раньше любая пара строк с « \| » считалась таблицей, а модель делала её пунктами |
| Р7 | Текст, которому нет поля в шаблоне, — ошибка «не встало в шаблон» с этим текстом, а не тишина. | вводный абзац над карточками без текстового поля | раньше такой текст пропадал молча |

## 4. В-правила: разметка при вставке

Срабатывают один раз, когда редактор нажимает «Разобрать» (`G.premark`, core.js), и при вставке HTML в поле текста (`G.htmlToMarkup`). Результат — обычная разметка: её видно в «Тексте» и можно поправить. Гриди пишет, какие правила сработали.

| № | Правило |
| --- | --- |
| В1 | HTML из буфера: h1 → `[h1]`, h2 → `[h2]`, h3–h6 → `[h3]`, li → пункт, img с alt → `[картинка]`, tr → строка таблицы, абзац-ссылка → `[кнопка] текст \| адрес`. |
| В2 | Список без маркеров: строка с двоеточием, за ней 2 строки и больше на «;», последняя на «.» — пункты. |
| В3 | Строка «Текст \| https://…» без разметки — кнопка. |

## 5. С-правила: сборка без модели

`G.assemble` (llm.js). Это черновик для модели и запасной вариант, если модель не ответила.

**Лендинг:**
- **С1.** Блоки — по `[h1]`, `[h2]`, `---`. Текст до первого заголовка — первый экран.
- **С2.** Роль блока — по словам в его заголовке (`keys` роли в сценарии, затем слова из названия и смысла роли). Каждая роль — один раз. Последний блок из одних кнопок — целевое действие.
- **С3.** Таблица без пунктов — шаблон «Таблица».

Если в тексте нет ни `[h1]`, ни `[h2]`, без модели страница собирается почти одним блоком. Гриди пишет об этом и предлагает разобрать заново.

**Статья:**
- **С4.** `[h1]` — первый экран. Короткие строки сразу под ним (до 3, до 80 знаков, без точки в конце) — подписи `@`. Первый абзац после — лид.
- **С5.** `[h2]`/`[h3]` открывает раздел «Текст статьи». Подряд 2 и больше коротких подразделов `[h3]` с одним абзацем — один врез с карточками.
- **С6.** Список, картинки, таблица — врез. Короткая строка без точки прямо перед списком — заголовок вреза.
- **С7.** Кнопка забирает абзац над собой во врез. Абзац в кавычках с `@` под ним — врез-цитата.

## 6. М-правила: ответ модели

Промт — системный промт из сценария (`prompt`, по умолчанию «parse», library/prompts.js). Применение ответа — `G.applyParse` (llm.js).

**Что модель отвечает:** `{"blocks":[{"role","lines","title","items","meta","button","image","split","tip"}],"story"}`. Всё — номера строк.

- **М1.** Строки, размеченные автором, и строки таблицы защищены: модель их не переделывает.
- **М2.** `title` — заголовок: первый в блоке — `[h2]` (`[h1]` у первого экрана), следующие — `[h3]`. Уровень не зависит от места строки в блоке. До 120 знаков.
- **М3.** `items` — номер становится пунктом (до 300 знаков). Диапазон «4-5» — карточка: первая строка `[h3]`, остальные её текст.
- **М4.** `meta` — подпись `@` (до 120 знаков), `button` — `[кнопка]` (до 200), `image` — `[картинка]` (до 200).
- **М5.** `split: {"7": "Доклады"}` — строка 7 делится на «Доклады — остальное». Только если строка действительно так начинается. Это единственное, что Гриди добавляет в текст: разделитель « — ». Слова не меняются.
- **М6.** Роль не из сценария — роль из сборки Гриди. Строки, которые модель не разложила, — в конец, блок «Не разобрано». Потеряна больше четверти строк — страница по разметке, без ответа модели.
- **М7.** Соседние блоки первого экрана сливаются в один. Короткие строки без разметки в присоединённом блоке становятся подписями.
- **М8.** Текст длиннее `maxText` сценария: хвост собирается по разметке.

## 7. Сценарий

Сценарий — тип страницы: блоки-слоты по порядку. Из него собирается промт разбора. Файл — library/scenarios.js, редактор — «Библиотека → Сценарии».

| Поле | Что делает | Куда идёт |
| --- | --- | --- |
| `prompt` | тег системного промта разбора | какой промт берётся |
| `action`, `button` | целевое действие, подпись кнопки по умолчанию | промт, заполнение кнопки целевого действия |
| `rules` | уточнения разбора в терминах ролей и формы текста | раздел промта УТОЧНЕНИЯ СЦЕНАРИЯ |
| `roles[].name`, `meaning` | название и смысл блока | список ролей в промте, проверки |
| `roles[].req` | блок нужен | проверка «Нет блока» |
| `roles[].items` | пунктов максимум | промт |
| `roles[].example` | пример блока в разметке | пример в промте и самопроверка сценария |
| `roles[].keys` | слова в заголовке | роль при сборке без модели (С2) |
| `roles[].templates` | только эти шаблоны | подбор |
| `roles[].prefer` | предпочесть среди равных | подбор |
| `roles[].verbatim` | текст не переписывается и не режется | адаптация |

**Шаблоны в сценарии** указываются по id (`'a-17'`) или по типу и параметрам конструктора: `{type: 'Шаги', mark: 'время'}`. Названия старых сценариев тоже понимаются, но название меняется вместе с параметрами шаблона, поэтому новые ссылки — только id или тип.

**Пример в промте** собирается сам (`G.parseExample`). Гриди берёт `example` ролей, убирает разметку, нумерует строки и по правилам этого документа вычисляет правильный ответ. Отдельный пример поддерживать не нужно: он всегда совпадает со сценарием и с правилами. Если ни у одной роли нет примера, в промт идёт общий пример формы ответа. В промте пример подписан как пример формы, а не страницы: порядок и роли в настоящем тексте свои.

## 8. П-правила: подбор шаблона

`G.pool`, `G.score`, `G.rank`, `G.autoPick` (match.js).

**Кандидаты:**
- **П1.** У роли есть `templates` — только они.
- **П2.** Первый экран — только шаблоны с H1. Первым экраном считается блок с ролью «Первый экран», а не первый блок страницы.
- **П3.** Остальным — без H1 и H2: заголовок раздела — отдельный блок гриды.
- **П4.** Шаблоны «только для статьи» — только в статье. Компоненты сайта: по своей роли; таблица — если в блоке таблица; аккордеон — если в блоке вопросы.

**Оценка:** балл 100 минус штрафы, и уровень — что придётся менять.

| Уровень | Что значит | Примеры причин |
| --- | --- | --- |
| 0 | Подходит | |
| 1 | Сократить текст | длиннее лимита |
| 2 | Переписать в поля | пустое поле, пустая кнопка, таблица станет текстом |
| 3 | Изменить число пунктов | пунктов больше или меньше мест |
| 4 | Изменить текст под дизайн | пунктам нет места, в тексте кнопка — в шаблоне нет, не встало в шаблон (Р7) |

- **П5.** Кнопки в шаблоне — «до N»: меньше кнопок — нормально, нет ни одной — «пустая кнопка».
- **П6.** Больше 4 пунктов в сетке — ряды: 5 = 2 + 3, 7 = 3 + 4. Блок один, лимиты на каждый пункт.
- **П7.** Проверки формы:
  - время в начале всех пунктов → нужен шаблон с временем;
  - пункты «Имя Фамилия» или с подписями → «Люди»;
  - числа в пунктах → «Цифры»;
  - абзац с подписью → «Цитата»;
  - половина пунктов с «?» → вопросы, больше 4 — аккордеон.

**Порядок кандидатов:**
1. уровень;
2. пункты не слиты в текст шаблона без пунктов;
3. меньше текста не встало;
4. балл;
5. компонент для роли, затем рекомендован сценарием, затем есть в админке.

- **П8.** Шаблон из админки всегда раньше шаблона «нужен дизайн»: поменять текст дешевле, чем заказать дизайн. «Нужен дизайн» — только если в админке нет ничего. Гриди выбирает только из шаблонов библиотеки, новых не придумывает.

## 9. З-правила: заполнение полей

`G.autoFill` (match.js). Поля всегда собираются из текста блока заново.

- **З1.** Заголовок → поле заголовка. Если поля нет, `[h2]` блока ставится отдельным блоком «Заголовок» над шаблоном.
- **З2.** Абзацы → первое текстовое поле. Подписи → бейдж или подпись. Кнопки → поля кнопок по порядку. У целевого действия без кнопки — `button` сценария.
- **З3.** Пункты → элементы шаблона: заголовок, текст, подпись, кнопка. Что из пункта не встало в своё поле — в пустые поля этого же пункта.
- **З4.** Подпись без своего поля стекает в текст **того же** элемента: подпись пункта — в текст пункта новой строкой, подпись блока — первой строкой текстового поля блока. Между элементами ничего не переносится.
- **З5.** У шаблона без пунктов пункты дописываются в текстовое поле списком. Это сохраняет текст, но оценка — уровень 4, и такой шаблон стоит в конце очереди.
- **З6.** Правка полей в «Шаблонах» переписывает разметку блока (`G.valuesToMarkup`): «Текст» и «Шаблоны» всегда об одном.

## 10. К-правила: проверка

`G.checks` (match.js).

**Ошибки** (красный):
- нет блоков;
- два первых экрана или два целевых действия;
- H1 не в первом экране;
- текст не встал в шаблон (Р7).

**Предупреждения** (жёлтый):
- нет обязательного блока;
- нет H1 в первом экране;
- пустой блок;
- нет шаблона;
- уровень шаблона 3–4;
- поле длиннее лимита;
- кнопка без глагола («Подробнее»);
- пометка «нужно от автора»;
- ложная срочность;
- у статьи — полотно без врезов, мало врезов.

**Подсказки** (серый):
- порядок блоков отличается от сценария;
- роль повторяется;
- нужен дизайн шаблона;
- нет картинки или иконки;
- врезы одного вида.

**Правила Нави** (library/rules.js, общие с прототипом Нави):
- первый экран — первым блоком;
- у кнопки первого экрана есть целевое действие;
- подпись главной кнопки одна и до 24 знаков;
- целевое действие — в конце;
- оглавление из заголовков.

## 11. Ф-правила: «Поправить»

**Кодом**, без модели (`G.fixByCode`, llm.js). Текст не меняется, только разметка и порядок:
- **Ф1.** `[h1]` не в первом экране → `[h2]`.
- **Ф2.** Второй первый экран или второе целевое действие → обычный блок.
- **Ф3.** Первый экран не первым → наверх.
- **Ф4.** Вводный текст над пунктами без места в шаблоне → отдельный блок над ними.
- **Ф5.** Кнопки блока без места в шаблоне → отдельный блок сразу после.

**Моделью** (промт «Исправить по проверке»): длиннее лимита, пустые поля, число пунктов — по замечаниям проверки.

## 13. Тесты

`node tests/run.cjs` — проверка для разработки. В Гриди она не загружается и пользователям не видна: это как прогон эталонов перед выкладкой.

**Что проверяет:**
- **Статьи.** Шесть статей с sber.bank.in и sberbusiness.live (fixtures/*.lines.json): без модели и с ответами разного качества текст целиком, кнопки на месте, мусор в ответе не ломает страницу. Эталон редактора (burmalda.manual.json) — сборка совпадает с ручной.
- **Лендинг.** Эталонная страница мероприятия в ручной разметке (event-hand.md) и тот же текст без разметки (event-plain.md). Ответы DeepSeek, GPT и GigaChat, полученные 21.10 (event-*.json), должны давать то же:
  - текст целиком;
  - 3 кнопки со ссылками;
  - таблица в таблице;
  - всё встало в шаблоны после «Поправить»;
  - первый экран первым.
- **Правила.** Р2, Р3/Р4, Р5, Р6 и В3 на коротких примерах.

Правите правило — запустите тесты. Если тест упал, либо правка что-то сломала, либо правило поменялось намеренно: тогда поправьте и тест, и этот документ.
